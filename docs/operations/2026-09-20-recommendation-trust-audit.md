# 매모지 추천 신뢰성 조사

조사일: 2026-09-20. 관점: 월급으로 장기간 주식을 적립하려는 30세 직장인.

## 판정과 조사 범위

분석 정보를 모아 보여주는 도구로서 기반은 있으나, 증액/감액/중단을 따라 적립 금액을 바꿀 만큼 투자 효과가 검증됐다고 판단할 수 없다. 이전 대화에서 반복한 '마지막 튜닝', '거의 완성'은 소프트웨어 구현 진척이며 금융적 타당성 인증이 아니다.

이번 조사는 현재 소스, Flutter 표시 코드, 저장된 2026-09-19 샘플 리포트, 선택한 백엔드 테스트를 대상으로 했다. 운영 DB를 새로 조회하거나 기업 공시 원문과 현재 지표를 대조하지 않았다. 운영 뉴스 원문/생성 요약 쌍의 사실성, Google 가입, 실기기 화면 전체 흐름은 검증 완료로 간주하지 않는다.

## 2026-09-27 1차 보완 결과

- Finnhub 비율 필드를 값 크기로 추측하지 않고, 문서화된 퍼센트 포인트 단위에서 명시적으로 100으로 나누도록 수정했다. 0.5%, 1%, 13.25%, -0.5% 경계 테스트를 추가했다.
- 미국 시장 기준일로 7일을 넘긴 가격 스냅샷은 7일/30일 가격 점수와 증액 판단에 사용하지 않도록 차단했다. 최신성 경계 테스트를 추가했다.
- 자료 충족도 계산에서 투자 시작일과 사용자 메모 가점을 제거하고 홈·상세의 기본 기준을 통일했다. 화면 명칭도 적중 확률처럼 읽히는 `신뢰도`에서 `자료 충족도`로 변경했다.
- 자료 충족도를 현재가·7일/30일 흐름·시총·PER·EPS·매출성장·영업이익률·ROE·분석 뉴스의 실제 존재 여부로 다시 계산했다. 핵심 재무자료가 비어 있는 종목이 80~90%로 표시되던 문제를 차단했다.
- 한국어 뉴스 요약 생성에 실패하면 일반적인 분석 문장을 만들어내지 않고, 실패 사실과 원문 확인 필요성을 표시하도록 변경했다.
- 전체 백엔드 테스트 204건 중 185건이 통과했고 19건은 환경 조건상 제외됐으며 실패는 0건이다. Flutter 추천 상세 화면 정적 분석도 통과했다.

### 가격 안정성 경로 보완

- 최근 31개 유효 가격으로 일별 수익률 표준편차와 최대낙폭을 계산해 기존 7일·30일 종점 기반 안정성 점수와 혼합한다.
- 유효 관측치가 10개 미만이거나 경로 계산에 실패하면 기존 계산으로 대체해 신규 상장 종목을 임의로 안정적이라고 판단하지 않는다.
- 동일한 7일·30일 수익률이라도 중간 변동성과 최대낙폭이 큰 경로가 더 낮은 점수를 받는 회귀 테스트를 추가했다.

이번 보완은 명백한 단위·최신성·표현 오류를 줄인 것이다. 과거 추천의 수익성, 뉴스 요약의 사실성, 실제 공시 대비 재무 데이터 정확성을 입증한 것은 아니다. 아래 발견 사항 중 가격 경로 변동성, 뉴스 표본 검수, 시계열 모의검증은 계속 출시 전 검증 대상으로 남는다.

## 우선순위별 발견 사항

### P1: 데이터의 존재와 최신성이 혼동된다

- `RecommendationService.java:5831` 부근에서 최신 행을 조회하나 내부 `PriceSnapshot`에는 기준일/공시일/출처가 없다(`6067`). 외부 보강 실패 시 기존 행으로 계산을 이어간다.
- `StockPriceSnapshotBatchService.java:144` 부근은 새 지표가 null이면 이전 EPS/ROE/성장률 등을 복사한다. 공시 지표 재사용 자체는 타당하지만 개별 지표의 원래 기준일이 계산 입력에 전달되지 않으면 오늘 수집한 자료와 구별할 수 없다.
- 저장된 샘플표에는 133행 중 122행이 2026-09-01 이전 스냅샷이다. 예: MSFT 등의 최신성은 개별 확인이 필요하며, 표에서 CMCSA 08-13, EOG 08-14 자료가 높은 점수로 등장한다. 이는 해당 리포트의 한계이며 모든 운영 사용자 추천이 오래됐다는 뜻은 아니다.
- 완료 기준: 가격의 시장 기준일, 지표의 회계기간/공시일/수집일/출처 구분. 오래된 가격 또는 핵심 입력 공백 시 증액 제한. 허용 신선도는 거래일 기준으로 정의하고 테스트.

### P1: 표시된 신뢰도는 적중 확률이 아니다

- `RecommendationService.java:5789`의 계산은 기본 55에 현재가 +5, 30일 흐름 +10, 투자 시작일 +5, 메모 +5, 뉴스 분석 신뢰도 일부를 더한다.
- `lib/screens/stock_detail_screen.dart:252`는 이를 `신뢰도`와 `%`로 보여준다.
- 동일 기업/동일 재무 상태에서도 메모와 시작일 입력만으로 70에서 80이 될 수 있다. 이는 예측 성과나 확률의 교정이 아니다. 증액 자격에도 confidence가 쓰인다.
- 완료 기준: 자료 충족도와 예측 신뢰를 분리. 실증 교정 전에는 적중률처럼 읽히는 퍼센트 제거. 사용자 메모가 종목 예측 확신을 올리지 않도록 재설계.

### P1: 가격 안정성은 실제 경로 변동성을 측정하지 않는다

- `RecommendationService.java:2882`는 7일/30일 누적 수익률 절댓값 및 음수 부분으로 stress를 계산한다. 한쪽 값이 없으면 해당 항을 0으로 둔다.
- 일별로 크게 출렁인 후 원래 가격에 복귀한 주식과 가격이 거의 변하지 않은 주식은 두 구간 수익률이 같으면 같은 안정성 점수를 받는다. 실제 변동성과 최대낙폭은 전혀 다를 수 있다.
- 완료 기준: 일별 수정주가의 수익률 변동성, 하방 변동성, 최대낙폭, 유효 관측 수 계산. 부족한 구간은 안정으로 간주하지 않기. 같은 시작/끝 가격이지만 경로가 다른 반례 검증.

### P1: 뉴스 요약의 입력 범위와 실패 상태가 과장되어 보일 수 있다

- `NewsSentimentService.java:692`의 프롬프트는 Finnhub 제목 최대 180자, 제공 요약 최대 320자만 전달한다. 기사 전문을 읽은 분석이 아니다.
- '이미 주가에 반영' 등의 판단을 요청하지만 해당 프롬프트에는 가격 자료나 시장 기대치가 없다. 이 부분은 LLM이 근거 없이 추정할 위험이다.
- `1363` 부근은 한글이 한 글자라도 있으면 한국어 결과로 통과시킨다. 의미/수치/부정 표현 검증은 아니다.
- `1386` 부근의 실패 대체문은 영어 제목을 인용하고 '핵심 흐름을 반영했습니다'라고 설명한다. 실질 요약 실패를 사용자가 알기 어렵다.
- Gemini 실패 시 키워드 fallback이 악재 키워드를 근거로 hard-negative 경로에도 들어간다(`842` 부근). '파산 위험 해소' 같은 부정/해소 문맥에 취약한지 별도 반례가 필요하다.
- 완료 기준: 제공 요약 기반임을 명시, 실패 상태 별도 표시, 근거 없는 주가 반영 주장 금지. 뉴스 50건의 입력/요약/원문 쌍을 사람이 비교하여 숫자·기업·부정 표현·날짜·출처를 검수. 키워드 fallback만으로 강한 조치가 내려지는 경로 제한.

### P1: 투자 성과 검증이 확인되지 않는다

- 점수 구조는 입력 지표에 임계값/가중치/교차 보정을 적용하는 규칙 기반 모델이다. 여러 재무 축을 쓰는 것은 장점이나 그 자체가 수익성 증거는 아니다.
- 확인한 docs 및 backend 테스트 검색에서 거래비용/시점별 공시 가용성/비교 전략을 갖춘 시계열 백테스트 또는 외부 검증 결과를 찾지 못했다.
- 샘플 리포트는 현재 스냅샷과 기본 설정으로 점수를 재계산한다. 실제 사용자 뉴스/환경별 설정/자금 사정을 모두 재현하는 운영 성과표가 아니다.
- 완료 기준: 모델 버전과 설정을 고정하고 이후 기간에 모의 추적. 단순 동일 금액 적립과 동일 현금 유입 조건에서 비교. 감액/중단으로 남은 현금, 거래비용, 낙폭, 회전율, 미투자 기회비용 포함. 과거 검증 시 공시 후에만 지표 사용하고 수정주가/상장폐지/생존편향 처리. 특정 유명 종목이 원하는 상태가 되도록 조정하는 것을 성공 기준으로 삼지 않기.

### P1: 퍼센트 단위 판별은 값의 크기로 해서는 안 된다

- `StockPriceSnapshotBatchService.java:1330`의 `normalizePercent`는 절댓값이 1 초과면 100으로 나누고 나머지는 그대로 둔다.
- 퍼센트 단위 원본 0.5가 주어졌다면 0.005여야 하나 0.5로 저장되고, 1.01은 0.0101로 변환되어 경계에 불연속이 생긴다. 반대로 비율 단위 1.2도 잘못 축소될 수 있다.
- 이 위험은 코드로 확인했다. 어떤 운영 종목이 실제 영향을 받았는지는 provider 원응답/계약과 저장값 대조가 필요하다.
- 완료 기준: 공급자/필드별 단위 명시, 0.5/1/1.01/-0.5 및 100% 초과 값 경계 테스트, 영향 행 선별 후 재적재.

### P2: 현금흐름 지표의 분모가 달라질 수 있다

- `StockPriceSnapshotBatchService.java:1337`의 `deriveFreeCashFlowYield`는 `currentEv/freeCashFlowTTM`의 역수를 사용한다. 이는 FCF/EV이며 일반적인 주주 관점 FCF/시가총액과 다르다.
- 다른 provider의 FCF yield와 같은 칼럼에서 섞이면 같은 의미의 값이라는 보장이 없다. 부채가 큰 기업일수록 차이가 크다.
- 완료 기준: FCF/EV와 FCF/시가총액의 정의를 분리하고 공급자별 계약 및 화면 설명 일치 확인.

### P2: 개인화는 생활 재무상황을 판단할 정도로 충분하지 않다

- `RecommendationTarget`의 개인 입력은 적립금액, 보유수량, 시작일, 메모, 성향 등이다. 월 가용예산, 비상자금, 부채상환, 전체 자산 집중도는 해당 판단 입력에 없다.
- `RecommendationService.java:5779`는 증액 x1.2, 감액 x0.7, 중단 0을 적용한다. 여러 종목의 동시 증액을 감당할 수 있는지 이 함수는 알지 못한다.
- `InvestmentDnaScorer`는 12문항의 1~5점 단순 합산이다. 소비절제/투자관심과 손실감내 능력은 같지 않으며 현재 분류가 적합성 검증을 통과했다는 증거는 확인하지 못했다.
- 완료 기준: 금액 제안의 적용 범위와 한계 표시, 전체 적립 예산 상한 확인. STOP이 보유 주식 매도가 아닌 신규 적립 중단임을 일관되게 설명.

## 확인된 장점

- 가격/뉴스/기업체력/밸류에이션/성장의 질/사용자 적합도의 가중치가 코드와 설정으로 추적 가능하다.
- 증액에는 점수 이외 데이터 및 충돌 조건을 추가로 확인한다.
- factor details와 모델 버전 저장 구조, 뉴스 캐시와 출처 URL 구조가 있다.
- 이번 선택 테스트: 계산기 34, 기업체력 11, 섹터 9, 뉴스 7, 수익률 3, 스냅샷 13 = 총 77건 성공, 실패/제외 0. 모두 로컬 검증이며 Gemini 생성 품질이나 투자 수익률을 인증하지 않는다.

## 유한한 마감 순서

1. 단위/지표 정의/자료 기준일 수정 및 영향 데이터 감사.
2. 신뢰도 표시와 뉴스 실패 표시 수정, 오래된 자료의 증액 제한.
3. 가격 안정성 경로 반례 및 실제 뉴스 50건/재무 표본 10개 공시 대조.
4. 알고리즘 버전 동결 후 독립 기간 모의 검증. 부진한 결과도 보존.

1~3 통과는 정보 제공 중심 제한 베타의 판정 근거가 된다. 4 전에는 '수익을 높이는 검증된 추천'이라는 주장을 하지 않는다. 무기한 유명 종목 점수 미세조정보다 이 기준으로 마감한다.
